Reading the wiring

  1. Three collections are deliberately shared, not tenant-scoped: Vehicle, OwnerProfile, and Tenant itself. A single vehicle can be serviced by staff from several different tenants — the isolation boundary for it is authorizedServiceCenters[], not tenantId.
  2. Permission, SubscriptionPlan, and Role are global catalogs, seeded once and read by every tenant — closer to static reference tables than to per-tenant business data. (They had briefly picked up tenant scoping by mistake, which silently broke permission/plan lookups for any real request — since reverted.)
  3. Reminder, Invoice, and Subscription were added 2026-08-24 to close out three ref/refPath fields (on Notification, OwnerProfile, and Payment) that previously pointed at collections with no model file — those populate() calls would have thrown MissingSchemaError the moment anyone used them. Note Subscription is distinct from SubscriptionPlan: the plan is the catalog of what can be bought, the subscription is a purchased billing-period instance.
  4. A vehicle's mileage is tracked in three independent places — Vehicle.currentOdometer, the embedded snapshot on each ServiceRecord, and the standalone OdometerReading collection — with no schema-level mechanism keeping them in sync; whatever service code writes them is the only source of truth for consistency.
